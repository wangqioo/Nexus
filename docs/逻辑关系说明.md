# Nexus 当前逻辑关系说明

用于对齐「项目类型、.nexus、知识库、笔记库、同步、一键加载、面板与跳转」的完整关系。

---

## 一、项目类型（Project Type）

- **作用**：给项目打标签、在「笔记」里按类型筛选、知识库按类型分目录存放、移动项目到对应 Workshop 目录。
- **与 .nexus 的关系**：**.nexus 不按项目类型区分**，所有项目用同一份模板；项目类型只影响「存到哪个 knowledge/<类型> 目录」和「笔记面板按类型筛选」。
- **内置类型**：mcu、ai、software、linux、mobile、remote（见 `PROJECT_TYPE_DEFS` / 前端 `PROJECT_TYPES`）。
- **自定义类型**：用户可新增，存于 `~/.nexus/custom-project-types.json`，统一归到 Workshop/Other。

---

## 二、.nexus 模板（一份统一）

- **唯一配置来源**：`~/.nexus/templates.json`（应用内「模板设置」编辑的就是它）。
- **初始化 / 同步 / AI 生成**：一律用 `loadTemplateConfig()` 读这一份，不再按项目类型选不同模板。
- **内容**：包含 4 类知识模板（debug、snippet、config、other）+ 笔记模板（note，用于 `.nexus/notes/`），以及通用设置（时间戳、默认标签、AI 分析开关等）。

---

## 三、.nexus 目录结构（每个项目下）

一键加载配置 / 初始化时，在项目根目录创建 `.nexus/`，下含 **5 个子目录**（由 `SIL_SUBDIRS` 决定）：

| 子目录      | 归属   | 说明 |
|------------|--------|------|
| `notes/`   | 笔记库 | 开发笔记，同步后只在「笔记」面板展示 |
| `debug/`   | 知识库 | 调试经验 |
| `snippets/`| 知识库 | 代码片段 |
| `configs/`  | 知识库 | 配置模板 |
| `other/`   | 知识库 | 其他 |

同时生成：

- `project.yaml`：项目 id、name、**projectType**、description、chip、framework、peripherals、tags 等。
- `templates.json`：与当前「一份模板」一致，但 **knowledgeCategories 强制为固定 4 类**（debug、snippet、config、other），不包含笔记（笔记只在 notes/）。
- `README.md`、`.cursor/rules/nexus.mdc`：说明目录用途和 Cursor 规则。

---

## 四、知识库 vs 笔记库（两条线）

- **知识库**
  - 只有 **4 类**：调试经验、代码片段、配置模板、其他。
  - 存储：`~/.nexus/knowledge/<项目类型>/*.json`（扁平），每条有 `category`（上述 4 类之一）、`projectType` 等。
  - 展示：在「知识库」页，可按项目类型 + 知识分类筛选。

- **笔记库**
  - `.nexus/notes/` 里的 .md 同步到 `~/.nexus/notes/*.json`。
  - 笔记**不入知识库**，只在「笔记」面板展示；可按项目类型筛选。
  - 每条笔记有 `projectType`、`sourceProject` 等，用于按项目归类和「已同步」关联。

---

## 五、同步流程（sil:syncFrom）

1. 读项目 `.nexus/project.yaml` 得到 **projectType**（缺省则用前端传入或路径推断）。
2. 用 **同一份** `loadTemplateConfig()`，不按类型选模板。
3. 扫描 `.nexus` 下目录：
   - **notes/** → 写入 `~/.nexus/notes/<项目名>-<文件名>.json`，带 `projectType`。
   - **debug、snippets、configs、other**（及未列出的归 other）→ 写入 `~/.nexus/knowledge/<projectType>/*.json`，每条带 `category`（4 类之一）。
4. 可选：AI 分析（API Key 从 config.json 或前端传入）补充 title、tags、metadata 等。

---

## 六、一键加载配置

- **入口**：项目管理页「一键加载配置」。
- **行为**：对选中的项目（可勾选「仅未初始化」）逐个执行「写入 .nexus」：
  - 用 **同一份** `loadTemplateConfig()`，再强制 `knowledgeCategories = FIXED_KNOWLEDGE_CATEGORIES_FOR_NEXUS`（4 类）。
  - 创建 5 个子目录、project.yaml（含该项目的 projectType）、templates.json、README、nexus.mdc。
- **结论**：所有项目的 .nexus 结构一致，不因项目类型不同而不同；项目类型只写在 project.yaml 里，用于同步时决定写进 knowledge 的哪个子目录。

---

## 七、项目管理面板（项目卡片打开后）

右侧详情里 Tab 顺序为：

1. **项目概览**：描述、介绍、功能特性等。
2. **笔记**：本项目 `.nexus/notes/` 下的文档列表（点条目可跳转到笔记页并打开该条）。
3. **调试经验**：本项目 `.nexus/debug/` 下的文档列表。
4. **代码片段**：`.nexus/snippets/`。
5. **配置模板**：`.nexus/configs/`。
6. **已同步**：已同步到中央知识库/笔记库的条目（按项目路径关联），以及「待清理」的已删除文档。

「查看」某条时：先按约定规则算 docId，检查是否已有对应 JSON（笔记查 `notes/<docId>.json`，知识查 `knowledge/<projectType>/...`）；若存在则跳转笔记/知识库页并打开该条，若不存在则提示先同步。

---

## 八、跳转与「未同步」提示

- **从项目面板点「查看」**：会跳到 `/notes?docId=xxx` 或 `/knowledge?docId=xxx`。
- **笔记/知识库页**：
  - 若 URL 带 `docId`，会**先刷新列表**（避免刚同步完列表还是旧的），再在列表中查找该 id 并打开详情；找不到则提示「未找到对应的笔记/知识条目，可能尚未同步」。
- **docId 规则**：笔记为 `{项目文件夹名}-{文件名无.md}`，与同步时写入的 JSON 文件名一致；知识库类似，带类型前缀。

---

## 九、数据存储汇总

| 数据           | 路径 |
|----------------|------|
| 模板配置       | `~/.nexus/templates.json` |
| 自定义项目类型 | `~/.nexus/custom-project-types.json` |
| 知识库         | `~/.nexus/knowledge/<项目类型>/*.json` |
| 笔记库         | `~/.nexus/notes/*.json` |
| 本地项目列表   | `~/.nexus/local-projects.json` |
| 应用配置       | `~/.nexus/config.json` 等 |

---

## 十、和「按项目类型分模板」的对比（已废弃）

- **以前**：不同项目类型可对应不同模板（如 mcu / software 各一套），初始化/同步时按 `getTemplateRef(projectType)` 选模板。
- **现在**：**.nexus 只认一份模板**，`templateRef` 仅作兼容保留；初始化、同步、AI 生成文档都只用 `loadTemplateConfig()`，不再按项目类型切换模板。

以上即为当前全部逻辑关系，可按此对齐产品与实现。
